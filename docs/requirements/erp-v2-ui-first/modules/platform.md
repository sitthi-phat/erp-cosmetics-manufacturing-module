## 4. Statuses / lifecycle
- **★ Login (auth choice):** หน้า login แสดง **สองทางเลือก** — (a) กรอก **username + password** (basic), หรือ (b) กด **"เข้าสู่ระบบด้วย Google"** (เฉพาะ user ที่มี Google account ผูกไว้; ถ้าอีเมล Google ไม่ match user ใด → error "บัญชี Google นี้ยังไม่ได้ผูกกับผู้ใช้ในระบบ"). ทั้งสองทางนำเข้า session เดียวกัน. **★ login สำเร็จ → เข้าหน้า Dashboard (landing)** — เห็นเฉพาะแผนกที่มี Read (`dashboard.md`).
- **★ Home-link (r20 — ปอนด์ Gate-1 2026-07-31):** **header logo + ชื่อ "ESSENCE Hub System" ทุกหน้า = คลิกได้ → นำทางกลับหน้า Dashboard (landing)**. เป็นทางกลับหน้าแรกมาตรฐาน (ไม่ต้องแก้ URL เอง) — สอดคล้อง Home-removed/Dashboard-landing rule; ไม่มีเมนู "หน้าหลัก (Home)" ในเมนูซ้าย.
- **★ First-login password change:** ถ้า user มี password mode = **must-change-on-first-login** → หลัง login (basic) ครั้งแรก ระบบพาไปหน้า **ตั้งรหัสใหม่ (2 ครั้ง + show/hide)** ก่อนเข้าใช้งาน (ตามเกณฑ์รหัส `non-functional.md` A9); ตั้งเสร็จ flag เคลียร์ → เข้า Dashboard. mode = **permanent** → เข้า Dashboard ได้เลย. **★★★★★★★ Abandonment:** ปิด/ออกก่อนตั้งเสร็จ → flag must-change **ยังอยู่**, login ครั้งถัดไปถูกบังคับตั้งใหม่อีก (A6).
- **★★★★★★★ Forget / Reset password (A12):** หน้า login มีลิงก์ **"ลืมรหัสผ่าน"** → หน้า request กรอกอีเมล → ระบบสร้าง **reset-token single-use อายุ 3 วัน** ส่งไป **อีเมลบนเรคคอร์ดผู้ใช้** → user เปิดลิงก์ → หน้า set-new ตั้งรหัส 2 ครั้ง + show/hide (ตามเกณฑ์ A9) → บันทึก → login ใหม่. **Edge/Error:** ลิงก์ >3 วัน → "ลิงก์หมดอายุ"; ลิงก์ single-use ถูกใช้แล้วกดซ้ำ → "ลิงก์นี้ถูกใช้แล้ว" (invalidated); อีเมลไม่ตรง active user (หรือบัญชี self-disabled/soft-deleted) → **ข้อความทั่วไปเสมอ ไม่เปิดเผยว่ามี/ไม่มีบัญชี (no account enumeration)** และไม่ปลดบล็อกบัญชีที่ถูกปิด. request/complete = **audit event** (ไม่เก็บค่ารหัส).
- **★★★★★★★ Account self-disable (A11):** ในเมนูผู้ใช้ มีปุ่ม **"ปิดบัญชีของฉัน"** → **confirm popup** (§9.1 NFR) → ยืนยัน → บัญชี = self-disabled + **audit event** → **session ปัจจุบันถูกตัดทันที** (request ถัดไป redirect login) → พยายาม login = **ถูกบล็อก** ("บัญชีถูกปิดใช้งาน กรุณาติดต่อผู้ดูแลระบบ"). **Re-enable = Admin เท่านั้น** (restore ผ่าน Settings). **★ Edge only-Admin (r20 pin):** ถ้าผู้ใช้จะ self-disable แล้ว **ไม่เหลือ user Active คนอื่นที่มี effective Settings level = Admin อย่างน้อย 1 คน** → **บล็อกการ self-disable + เตือน "ต้องมี Admin (Active) ในระบบอย่างน้อย 1 คน — มอบสิทธิ์ Admin ให้ผู้อื่นก่อน"**. (นิยามชัด: guard ผ่านก็ต่อเมื่อมี ≥1 other Active user ที่ effective Settings level = Admin.) **ไม่มี auto-lockout** ที่ใดในระบบ.
- **★★★★★★★ Notification (bell-only, ราย user) · ★★★★★★★★ r18 READ-DRIVEN:** event ใหม่ → เขียน outbox (J5) → fan-out ไปทุก user ที่มี **Read** ของ module ปลายทาง → ผู้รับเห็น **snackbar/toast ชั่วคราว + bell สั่น (shake)** + badge +1. **read-driven (read แทน dismiss):** **คลิกแจ้งเตือน** (ใน bell หรือหน้า "ดูทั้งหมด") = **navigate ไป deep-link ของรายการนั้น + mark READ (ราย user)** — การอ่านเป็นกลไกเดียวที่เคลียร์รายการ (A อ่านไม่กระทบ B) · **★ r20 optimistic badge: คลิก = mark read + ลด badge ทันทีฝั่ง client; poll ถัดไป (≤15s, P5) = reconcile ให้ตรง (backstop)** · รายการที่อ่านแล้ว **หลุดจาก bell ตอน refresh/poll ถัดไป** (near-real-time ไม่จำเป็น; ยอมรับ delay ของ poll — ไม่มี websocket/batch ซับซ้อน) · badge = จำนวน **ยังไม่อ่าน (unread)** · ปุ่ม **"อ่านแล้วทั้งหมด (mark all read)"** = mark ทุกแจ้งเตือนของ user เป็นอ่าน → bell เคลียร์ (ไม่กระทบผู้อื่น) · หน้า **"ดูทั้งหมด"** = ประวัติทั้งหมด (20/หน้า, จัดกลุ่ม 4 หมวด) แสดง **อ่าน/ยังไม่อ่าน** ไม่ถูกลบเมื่ออ่าน · **ยกเลิก ✕ dismiss ราย item + "ปิดทั้งหมด" เดิมทั้งหมด — read แทน dismiss.**
- **★★★★★★★★★ Notification EVENT SET + 4-หมวด grouping (r19 · r19.1 · r20 — ปอนด์ Gate-1 2026-07-31 · authoritative `non-functional.md` §7):** UI จัดกลุ่ม 4 หมวด; แต่ละ event ระบุ trigger→schedule→ผู้รับ(Read)→deep-link→read(per-user):
  1. **งานส่งต่อข้ามแผนก / เอกสาร (Workflow & Documents):**
     - **PO Confirmed→Production hand-off** (คงไว้) · **QC ตรวจรับ RM/Batch ผ่าน/ไม่ผ่าน** (คงไว้) · **PR auto-created** (คงไว้) — **near-real-time** · ผู้รับ = Read ของ module ปลายทาง (Production/Stock/QC/Procurement ตาม event) · deep-link = เอกสารปลายทาง.
     - **★ ใหม่ — เอกสารถูกยกเลิก/ปฏิเสธ (Document Cancelled / Rejected):** trigger = **QT · PO · SO · RT (Route) · DN · Invoice** (และเอกสารชนิดอื่นที่มี outcome cancel/void/reject) **ถูกยกเลิก / void / rejected**. **★ ไม่รวม soft-delete ที่ผู้ใช้ลบเอง** — การลบเรคคอร์ดโดยผู้ใช้ไม่ยิงแจ้งเตือน. **★ r20 clarify — ไม่รวม DN สถานะ "ลูกค้ายกเลิก (ยกเลิกการจัดส่ง)":** ผลการส่งราย DN = **"ยกเลิกการจัดส่ง" (cancel the *delivery*)** เป็น **delivery status** เท่านั้น — **ไม่นับเป็น event "เอกสารถูกยกเลิก/ปฏิเสธ"** และ **สถานะ order (PO/SO) ไม่เปลี่ยน** (order ยังอยู่; เป็นการยกเลิกรอบส่งไม่ใช่ยกเลิกใบสั่ง — `delivery-note.md` §7 / `shipping.md` §4b). ยิงเฉพาะ workflow outcome ยกเลิก/void/reject ของ *ตัวเอกสาร*. **near-real-time** · ผู้รับ = Read ของ module เอกสารนั้น · deep-link = เอกสารใบนั้น.
     - **★ ใหม่ — Route ส่งสำเร็จ (Route completed / delivered):** **★ r20 trigger = Route (RT) เข้าสถานะ "เสร็จสิ้น (Completed)"** — ข้อความ **generic** ("Route RT-… เสร็จสิ้น/ส่งสำเร็จ") ไม่อิงผล DN รายใบ (แม้บาง DN จะเลื่อน/ยกเลิกการจัดส่ง Route ก็ยังยิงใบสรุปเดียวตอนปิดรอบ). **near-real-time** · ผู้รับ = **Read Shipping/Route + Sale เจ้าของงาน (owning Sale)** (**★ r19.1/r20:** fan-out = Read Shipping/Route ∪ owning Sale ของเอกสาร/ลูกค้าต้นทางใน Route นั้น) · **★ r20 scope เฟสนี้:** Sale เห็น **ทั้ง Route / ทุก DN ในรอบ** — **ไม่ scope ราย DN**; ผลคือ Sale หนึ่งอาจเห็น order ของ Sale อื่นที่อยู่ในรอบเดียวกัน = **ยอมรับในเฟสนี้ (accepted, stated explicitly)** (per-DN scoping ไว้พิจารณารอบถัดไป) · deep-link = Route (RT) (และ/หรือ DN ที่เกี่ยวข้อง).
  2. **ความเสี่ยงสต็อก/การผลิต (Stock & Production risk):**
     - **potential-delay (J4)** (คงไว้ — PRD ใกล้ไม่ทันส่ง) · ผู้รับ = Read Production+Sale+Stock · deep-link = PRD.
     - **★ เปลี่ยน — สรุป Supply Planning Low + Overstock รายวัน (Daily summary):** trigger = **rollup รายวัน ~06:00 (J8)** สรุปสุขภาพสต็อกของวัน — **จำนวน FG ที่ Low + รายการ** และ **จำนวน FG ที่ Overstock + รายการ** เป็น **แจ้งเตือนสรุปรวมใบเดียว** (ไม่ใช่ราย item, ไม่ใช่ real-time). **schedule = daily**. ผู้รับ = Read **Supply Planning**. deep-link = **หน้า Supply Planning เดิม พร้อม filter query `?filter=low-overstock` (Low + Overstock)** — reuse หน้า SP (มี filter Low/OK/Overstock อยู่แล้ว, `supply-planning.md` §4/§5.1; ไม่สร้างหน้าใหม่). **★ ตัด FG→Low real-time** (พับรวมเป็นสรุปรายวันนี้ — reservation/planning math ของ FG→Low คงเดิม, เปลี่ยนเฉพาะการส่ง notification).
  3. **การเงิน/เครดิต (Finance):**

  - **★ การเปลี่ยนแปลง r19 มีเพียง:** (a) **ตัด Customer Inactivity** → แทนด้วย **Customer Follow-up** (#4) · (b) **ตัด FG→Low real-time** → พับเข้า **สรุป Low+Overstock รายวัน** (#2) · (c) **เพิ่ม** เอกสารถูกยกเลิก/ปฏิเสธ + Route ส่งสำเร็จ. **คงไว้ทั้งหมด:** PO→Production · QC ผ่าน/ไม่ผ่าน · PR auto-created · Invoice Overdue · potential-delay (J4).
  - **★ r19.1 correction (ปอนด์ 2026-07-31):** (1) **Route ส่งสำเร็จ** ผู้รับ = Read Shipping/Route **+ owning Sale** · (2) **Customer Follow-up** schedule = **near-real-time เท่านั้น** (ตัด light daily due-check).
  - **★ r20 Gate-1 reconciliation (ปอนด์ 2026-07-31):** (1) **Follow-up = flag-set-only** — ตัดถ้อยคำ "ครบกำหนด/due-date" ทั้งหมด (ลูกค้าไม่มี due-date) + **de-dup กับ event ที่ยิง noti เอง** · (2) **Route ส่งสำเร็จ = ยิงเมื่อ Route "เสร็จสิ้น" (generic)** + เฟสนี้ **Sale เห็นทั้ง route/ทุก DN** (ไม่ scope ราย DN) · (3) **DN "ยกเลิกการจัดส่ง" ไม่นับเป็น doc-cancel event และ order status ไม่เปลี่ยน** · (4) **single fan-out rule** (§6) · (5) **optimistic badge** (§7).
  - **★ ไม่มี email notification (bell-only)** · **session warning ≠ notification** (เป็น banner, ข้อล่าง).
- **Session:** active → (24 ชม. หมด หรือ 06:00 daily reset) → ต้อง login ใหม่; **★★★★★★★ เตือนล่วงหน้า 5 นาที (banner) + mid-action expiry → redirect login; งานที่ยังไม่บันทึก = ไม่ถูกบันทึก (zero mutation, ไม่กินเลข G8)** (A2).

## 5. User Stories (absorbed) + AC สรุป
- **US-PLT-01 (Must) — login (basic/Google choice) + first-login change + landing Dashboard + identity + session warning:** **★ หน้า login เสนอ 2 ทาง — basic (username+password) หรือ Google** → login สำเร็จ → **★ ถ้าโหมด must-change-first-login → บังคับตั้งรหัสใหม่ก่อน** → **★ เข้าหน้า Dashboard เป็นหน้าแรก (landing · ไม่มี Home)**; ทุกหน้าแสดง "ESSENCE Hub System" + logo + browser title. **★ r20: header logo + title = คลิกได้กลับ Dashboard ทุกหน้า.** **Edge:** Google account ไม่ผูก user → error; **★★★★★★★ ใกล้ reset 06:00 (หรือใกล้ครบ 24 ชม.) → banner เตือนล่วงหน้า 5 นาที "ระบบจะออกจากระบบเวลา … กรุณาบันทึกงาน"**; ถึงเวลา/หมดกลางคัน → redirect login (งานที่ยังไม่บันทึก = ไม่ถูกบันทึก). **Error:** รหัสผิด → "ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง" (ไม่บอกช่องไหนผิด) · **★ ตั้งรหัสใหม่ 2 ครั้งไม่ตรง → "รหัสผ่านยืนยันไม่ตรงกัน"** · **★★★★★★★ รหัสไม่ผ่านเกณฑ์ (A9) → error ระบุเงื่อนไขที่ยังไม่ผ่าน** · **abandonment: ปิดก่อนตั้งเสร็จ → ครั้งหน้าบังคับตั้งใหม่อีก**.

## 7. Validations
- **★ login: basic ต้องกรอก username+password; Google ต้องมี link ที่ตรงกับ user (ไม่ตรง → error).**
- **★ first-login change: ตั้งรหัสใหม่ 2 ครั้งต้องตรงกัน + ผ่านเกณฑ์ A9 ก่อนเข้าใช้งาน (โหมด must-change); ปิดก่อนเสร็จ = flag ยังอยู่.**
- **★★★★★★★ reset password: token single-use + หมดอายุ 3 วัน; รหัสใหม่ 2 ครั้งตรงกัน + ผ่านเกณฑ์ A9; อีเมลไม่ตรง/บัญชีถูกปิด → ข้อความทั่วไป (no enumeration).**
- **★★★★★★★ self-disable: confirm popup; guard "ต้องเหลือ Admin (Active) ≥ 1 คน (≥1 other Active user ที่ effective Settings level = Admin)"; session ตัดทันที; re-enable = Admin.**
- **★ login สำเร็จ → landing = Dashboard (ไม่มี route ไป Home) · ★ r20 header logo/title = home-link กลับ Dashboard.**
- global search ≥2 ตัวอักษร จึงยิงค้น.
